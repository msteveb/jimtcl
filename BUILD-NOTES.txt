BUILD NOTES - TCC INCOMPATIBILITIES AND KNOWN ISSUES
======================================================
Last updated: 2026-09-03

This file documents issues encountered when building with TCC 0.9.28rc,
workarounds applied, and unresolved problems.

----------------------------------------------------------------------
1. TCC STAGE 1: INCLUDE PATH ISSUE (RESOLVED)
----------------------------------------------------------------------
Problem:
  When using TCC as CC for the TCC configure script, the configure probe
  binaries cannot find stdarg.h. This causes "include file 'stdarg.h' not
  found" error.

Root cause:
  configure runs probe programs (./conftest) that need TCC to know where
  its own include files are. The un-installed TCC does not have a usable
  prefix.

Fix:
  Install stage-0 TCC before using it as CC for stage-1 configuration:
    make install  (installs to build/host/ with proper lib/tcc/include/)
  Then use build/host/bin/tcc (the installed binary) as CC.

----------------------------------------------------------------------
2. MINILUA: ARG TABLE NOT SET (RESOLVED)
----------------------------------------------------------------------
Problem:
  The initial minilua main.c did not set the `arg` global. Fennel's
  bootstrap/aot.lua uses `arg[1]` to get the source file argument, causing:
    "attempt to index a nil value (global 'arg')"

Fix:
  Rewrote main.c to populate the global `arg` table following Lua 5.x
  conventions:
    arg[-1] = interpreter path
    arg[0]  = script path
    arg[N]  = Nth script argument (N >= 1)

----------------------------------------------------------------------
3. FENNEL BINARY LAUNCHER BUILD: FAILS (DOCUMENTED, WORKAROUND)
----------------------------------------------------------------------
Problem:
  Building the standalone `fennel` binary launcher from src/launcher.fnl
  fails with:
    "Compile error in 'macrodebug' src/fennel/binary.fnl:210:
     src/fennel/macros.fnl:338: attempt to call a boolean value (global 'view')"

Root cause:
  binary.fnl's macrodebug macro uses the 'view' function, which is not
  available in the bootstrap phase (bootstrap/fennel.lua is v0.4.4-dev,
  missing view).

Workaround:
  fennel.lua (the library amalgamation) is built successfully from .fnl
  sources using the Lua 5.5 binary. A shell wrapper script is used as the
  'fennel' launcher instead of a compiled binary.

  The wrapper (bin/linux-x64/fennel) calls:
    lua build-support/fennel-launcher.lua "$@"

Status:
  Fennel 1.6.1 functionality is complete. Only the standalone self-contained
  binary (with embedded Lua) is missing; this requires fennel --compile-binary
  which itself requires a working Lua C library to link against.

----------------------------------------------------------------------
4. NEXTVI WINDOWS CROSS-COMPILATION: UNSUPPORTED (DOCUMENTED)
----------------------------------------------------------------------
Problem:
  Nextvi 7.4 uses POSIX-specific headers:
    - poll.h (no equivalent in TCC's Win32 headers)
    - termios.h (TTY control, no Windows equivalent)
    - sys/wait.h
    - sys/ioctl.h

  Building vi.exe for Windows with x86_64-win32-tcc fails at the first
  #include <poll.h> because TCC's bundled Win32 headers don't include it.

Status:
  Not resolved. Nextvi is a Linux terminal editor and does not have a
  Windows port. Would require significant porting effort or use of a
  compatibility layer (e.g., MinGW's poll.h shim).

----------------------------------------------------------------------
5. JIM TCL WINDOWS CROSS-COMPILATION: PARTIALLY INVESTIGATED
----------------------------------------------------------------------
Problem:
  Jim Tcl's build system uses autosetup (a Tcl-based configure system).
  Cross-compilation for Windows requires:
    1. Running autosetup with target=win32 (needs jimsh or tclsh)
    2. Generating jim-config.h and jimautoconf.h for Windows
    3. Providing Windows-specific compile flags

  The jim.h header requires jim-config.h which is generated by autosetup.
  Without it, compilation immediately fails.

Partial solution:
  Jim Tcl already has jim-win32.c and jim-win32compat.c for Windows support.
  A static jim-config.h for Windows could be hand-crafted, but this is
  non-trivial.

Status:
  Not automated. Requires manual config.h creation or running autosetup
  on a Windows target or with a cross-configure script.
  Tracked as future work.

----------------------------------------------------------------------
6. TCC C99/C11 LIMITATIONS (GENERAL NOTE)
----------------------------------------------------------------------
TCC 0.9.28rc (mob branch) does not fully support:
  - All C11 features (_Generic, _Static_assert in some contexts)
  - C++ (jim-mk.cpp requires g++ or clang++)
  - GCC-specific extensions (__attribute__ mostly works, but edge cases exist)
  - -MMD dependency tracking flags (silently accepted but may not work)

Components that require g++ (NOT compiled with TCC):
  - jim-mk.cpp (Metakit binding) - excluded from build

----------------------------------------------------------------------
7. FENNEL AOT BOOTSTRAP: VERSION MISMATCH (DOCUMENTED)
----------------------------------------------------------------------
The bootstrap/fennel.lua in the Fennel 1.6.1 repo is version 0.4.4-dev.
This is intentional - it's the minimum compiler needed to AOT-compile
the current Fennel sources into fennel.lua.

The build works because:
  bootstrap/aot.lua (using bootstrap/fennel.lua) compiles .fnl -> .lua
  Then lua (our MiniLua) runs the compiled result.

----------------------------------------------------------------------
8. MAN PAGE GENERATION: SKIPPED (NON-CRITICAL)
----------------------------------------------------------------------
TCC does not generate man pages. The following tools are used by TCC's
Makefile but are not required for the binaries:
  - makeinfo (texinfo): for tcc-doc.info
  - pod2man: for tcc.1 man page

These are present on the build system (Ubuntu 24.04) and are called by
make, but their output is not included in vendored builds.

BOOTSTRAP ASSUMPTIONS
----------------------------------------------------------------------
  1. Host has GCC >= 4.8 or Clang (for stage 0 TCC build)
  2. Host has GNU make >= 3.81
  3. Host has POSIX sh, perl (for TCC docs, optional)
  4. Host has python3 (optional, for some TCC tests)
  5. Network access: only during vendoring (phase 3), not during build

----------------------------------------------------------------------
UNRESOLVED WINDOWS ISSUES
----------------------------------------------------------------------
  1. Nextvi: no Windows port exists
  2. Jim Tcl: Windows cross-config not automated
  3. Wine not available in build environment for testing .exe files
  4. No way to test Windows binaries without Wine or a Windows VM
